# Документы — этап 10, части 1–3

Реестр и закрытые копии PDF/JPEG/PNG дополнены девятью PDF-формами.
Свидетельство, племенные формы и новые права подробно описаны в
[documents-breeding.md](documents-breeding.md). Формы мероприятий описаны в
[documents-events.md](documents-events.md). Сводный отчёт реализован отдельной
[четвёртой частью](reports.md), без записи в реестр документов. Дополнительные
формы и редактор шаблонов отложены. Подробная дрессировка также не реализуется здесь.
Основание: ТЗ §3.4, §4.7, M7–M8; актуальная предметная область, с. 2–3.

## Права и связи

| Профиль | Доступ |
| --- | --- |
| staff | Реестр и чтение всех документов; создание/исправление/отмена обычных и племенных документов, загрузка их копий, печать соответствующих форм |
| veterinarian | Медицинские документы: чтение, реквизиты, копии, отмена; новое ветеринарное заключение только по собственному неотменённому осмотру |
| leader | Чтение всех документов, файлов и истории |
| expert | Чтение племенных документов и документов назначенных ему мероприятий, файлов и истории |
| owner | Только чтение/скачивание разрешённых документов при активном членстве |
| admin | Доступа к этому модулю нет |

Один активный профиль на сессию; профессиональные полномочия не складываются.
Для работы с медицинскими документами ветеринару нужна связь аккаунта с карточкой
человека. Другие профили аккаунта администратора действуют самостоятельно.

У новой записи один предмет: member_id, dog_id либо мероприятие для общей формы
(правила event_id и результата — в documents-events.md). Для документа человека
получатель совпадает с человеком. Для документа собаки recipient_member_id
необязателен: без него документ доступен только профессиональным профилям.
При указании получателя он должен быть текущим владельцем собаки.
При скачивании владелец должен одновременно оставаться получателем и текущим
владельцем; передача собаки закрывает доступ прежнего владельца и не раскрывает
его документы новому. Для нового владельца создают отдельную запись.
После прикрепления файла нельзя менять предмет, получателя или тип записи.

Карточка собаки содержит имя получателя-владельца без контактов других
совладельцев. Карточка человека содержит его контакты и адреса. История owner
возвращает before/after=null. Снимки, storage_key и пути не выдаются через API.
Старую связь club_member_id система не считает ни автором, ни получателем.

## Реестр и неизменяемые файлы

Реквизиты: number (до 50 символов), type_id, issuer (до 2000), необязательные
issue_date/expires_on, предмет и получатель. Даты YYYY-MM-DD; окончание не раньше
выдачи. Номер не является глобально уникальным: разные организации могут иметь
одинаковые номера. Неизвестные даты и номера не генерируются автоматически.
Статусы: legacy, active, void. legacy требует явного уточнения сотрудником
или ветеринаром в зависимости от выбранного типа. Отмена окончательная;
вместо восстановления отменённого документа создаётся новая запись.

Все исправления, загрузки, генерации и отмены расходуют общую version документа.
Нужны текущая version и непустая reason до 500 символов. История document_changes
атомарна с реквизитами и метаданными файлов. Конфликт версии — HTTP 409.
Физического удаления документов и отдельных файлов в API нет.

Файлы добавляются как отдельные неизменяемые версии. В реестре сохраняются
их размер, SHA-256, исходное имя, MIME, версия документа и автор-профиль.
Документ может иметь несколько файлов; загрузка нового не заменяет прежние байты.
Превышение размера — 413, неподдерживаемый или несогласованный формат — 422.
Разрешены application/pdf, image/jpeg, image/png, до 10 МиБ на файл.
Расширение должно соответствовать типу и сигнатуре. Для изображений проверяется
заголовок формата и размеры (до 40 мегапикселей). Для PDF проверяются заголовок
и завершающий маркер: это не полная проверка структуры/подписей или антивирус.
Файлы не исполняются, не преобразуются сервером и не показываются inline.

Скачивание всегда через API: attachment, no-store, nosniff и CSP sandbox.
Перед выдачей проверяются размер и SHA-256. Нет публичной статической папки,
постоянных URL с обходом авторизации, доверия клиентскому пути или имени.
Права, профиль, сессия и членство проверяются до дискового чтения и повторно после.
Отменённые/истёкшие документы доступны как история; status/expired не дают
предметного разрешения на участие или вязку.

## Печатные формы первой части

Шаблоны встроены в код, версия формы 1. PDF создаётся в Go, без внешнего браузера
или офисного сервера. Закреплены go-pdf/fpdf v0.9.0 и DejaVu v0.3.4; кириллица
встроена в PDF. Лицензионные уведомления — THIRD_PARTY_NOTICES.md, их необходимо
передавать с бинарным файлом.

- member_card: тип «Карточка члена клуба», человек, контакты/адреса/членство и его
  текущие собаки. Предельный объём одной формы — 1000 собак, без молчаливой обрезки.
- dog_card: тип «Карточка собаки», идентификатор, порода/пол/окрас/дата рождения,
  рост/вес, номер и выдавшая родословную организация, получатель, вакцинации.
  Отменённые вакцинации помечаются; максимум 1000 записей, без обрезки.
- veterinary_conclusion: тип «Ветеринарная справка», examination_id обязателен;
  clearance_id необязателен и должен относиться к тому же осмотру и собаке.
  Состояние, результат, рекомендации, диагнозы, а при выборе допуска — его решение,
  срок и выбранные вакцинации. Отсутствие выбранного допуска не трактуется как
  разрешение. Нельзя выпускать новую форму по отменённому осмотру/заключению
  или по осмотру с неизвестным/другим автором. Подпись остаётся строкой для подписи;
  электронная подпись и печать организации не подделываются и не добавляются.

Сохраняется точный снимок источников, выбранных оснований и реквизитов. При чтении
реестра файлу рассчитывается source_changed: исходные сведения отличаются от
снимка. Сам PDF при этом не меняется; для новой формы выполняют новую генерацию.
Для загруженной копии source_changed=null: система не знает её структурированного
источника. В непосредственном ответе мутации это поле также может быть null;
GET документа возвращает актуальную проверку для сформированных файлов.
expired вычисляется по expires_on на текущую дату UTC, независимо от изменения
источников и отмены. Сроки медицинских оснований показываются в форме отдельно;
медицинский допуск продолжает проверять veterinary, а не PDF-файл.

## Хранение и резервирование

DOCUMENTS_DIR по умолчанию var/documents, относительно рабочей папки API.
Для эксплуатации задайте постоянный абсолютный путь вне репозитория. Каталог
должен быть закрыт от других пользователей ОС (0700), файлы — 0600. Путь и
содержимое папки не включаются в Git; локальная var игнорируется.
Если каталог отсутствует, сервер создаёт его; небезопасные права существующего
каталога приводят к безопасной ошибке запуска. Содержимое каталога не обслуживается
веб-сервером напрямую. Используется os.Root и случайный ключ; переходы ../,
пользовательские имена на диске и чтение символьных ссылок не допускаются.

Генерация PDF и дисковые операции выполняются вне auth-транзакции. Затем
повторно проверяются доступ, версия и снимок источников. Файл записывается с
O_EXCL, fsync файла и каталога до commit метаданных. При известном откате новый
файл удаляется; при неоднозначном результате commit он сохраняется, чтобы не
удалить возможный зарегистрированный файл. После аварий может остаться закрытый
файл без строки БД; он недоступен через API. Автоматической очистки нет.

Резервная копия обязана охватывать PostgreSQL и DOCUMENTS_DIR согласованно.
Простой локальный порядок: остановить API, сохранить БД и папку файлов, затем
запустить API. Восстанавливать оба компонента из одной точки. Утерянный или
повреждённый файл даёт 503, а не выдаётся частично. Перенос на внешнее объектное
хранилище и специальная команда обслуживания не входят в эту часть этапа.

## API и ручная проверка

Полные DTO — [OpenAPI](../api/openapi.yaml); всего 139 операций сервера, включая подтверждение даты регистрации собаки и отчёты.

| Маршрут под /api/v1 | Назначение |
| --- | --- |
| GET /document-types | Тринадцать типов с категориями general/medical/breeding |
| GET/POST /documents | Реестр и новая запись |
| GET/PUT /documents/{documentID} | Чтение и исправление реквизитов |
| POST .../void | Отмена |
| POST .../generate | Генерация PDF по template и основаниям |
| POST .../files | Копия: multipart/form-data, поля file/version/reason |
| GET .../files/{fileID} | Скачивание файла |
| GET .../history | История |

Курсор after/limit, по умолчанию 20, максимум 100. Фильтры реестра: number
(подстрока без SQL wildcard), type_id, member_id (предмет или получатель), dog_id,
from/to (включительные даты выдачи). Неизвестные JSON-поля отклоняются,
JSON до 16 КиБ. RFC9457: document_conflict (409), documents_unavailable (503),
422 для неверных полей, 403 для профиля/неактивного членства, 404 для скрытого файла.

После запуска по README войдите нужным профилем, сохраняя access-токен в переменной
и не печатая его. Создайте запись подходящего типа, затем POST .../generate:

```json
{"version":1,"reason":"Печать карточки","template":"dog_card"}
```

Полученный files[].id используйте для GET .../files/{fileID}; сохраните PDF и
проверьте печать. Для копии (DOC_ID/VERSION/TOKEN задайте локально):

```bash
curl --fail-with-body -X POST "http://127.0.0.1:8080/api/v1/documents/$DOC_ID/files" \
  -H "Authorization: Bearer $TOKEN" \
  -F "version=$VERSION" -F 'reason=Копия документа' \
  -F 'file=@/absolute/path/copy.pdf;type=application/pdf'
```

Проверьте старую версию (409), чужого получателя (404), блокировку профиля,
неактивное членство, передачу собаки, неверный формат (422), превышение размера
(413), исправление источника и неизменность старого файла. Owner не создаёт
документы и не загружает копии. Отмена не удаляет историю.

## Проверки

```bash
go test -race -count=1 ./...
export DOGCLUB_TEST_DATABASE_URL="$DATABASE_URL"
go test -race -count=1 -tags=integration ./...
go vet -tags=integration ./...
go build ./...
go mod verify
```

Интеграционные тесты создают и удаляют только свои базы, файлы используют TempDir.
Покрыты версии, история и откат, форматы/размеры/подмена, контроль целостности,
все девять шаблонов, изменение источника, роли/членство/владение/отзыв профиля,
реальные HTTP-ответы OpenAPI, сохранение legacy-связей и одиннадцать миграций Up/Down.
Визуально проверяются тестовые PDF с кириллицей и длинным многостраничным текстом.
