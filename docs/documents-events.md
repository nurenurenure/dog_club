# Документы мероприятий

Три формы дополняют [общий реестр](documents.md) и [регистрационные/племенные
формы](documents-breeding.md). Всего девять шаблонов. Основание: ТЗ, PDF 01,
с. 12 и модуль M6 на с. 27; актуальное описание, PDF 03, с. 3–4.
[Сводный отчёт](reports.md) формируется без серверного архива.
Титулы по результатам, дипломы людей и сертификаты отложены.

## Формы и источники

| template | Тип документа | Основание и выпуск |
| --- | --- | --- |
| event_participants | Список участников мероприятия | event_id; после публикации, кроме отменённого мероприятия |
| event_protocol | Протокол мероприятия | event_id; только completed |
| event_diploma | Диплом | event_id + event_result_id + dog_id + получатель; только completed |

Список включает все неотменённые регистрации, в порядке ID. Собаки с
представителями и люди без собак разделены; регистрация той же собаки в другом
классе остаётся отдельной строкой. Это не подтверждение медицинского допуска.

Протокол включает только собак с явкой. По каждому выступлению выводятся класс,
действующие оценка и место, эксперт; отсутствие результата отмечено явно.
Отменённые результаты и записи без явки не включаются в итоги. Люди без собак
не получают оценку животного и в этот протокол не входят.

Диплом относится к конкретному результату зарегистрированного выступления
с подтверждённой явкой. Для нового выпуска нужен неотменённый результат с оценкой
или местом. Результат с одним свободным комментарием не даёт диплом.
Нельзя выбрать результат другой собаки или мероприятия. Отмена старого результата
не перепривязывает документ к заменившему его результату: нужна новая запись.

Мероприятие и его период берутся из events, даты выводятся в его часовом поясе.
Собака и класс результата — из сохранённого снимка выступления, если он есть;
старым данным без такого снимка факты не выдумываются. ФИО эксперта — из связанной
карточки, без логина/email; при отсутствии связи оно явно неизвестно.
Титул не вычисляется из оценки/места и не копируется из общего списка титулов
собаки: структурированной связи с конкретным выступлением пока нет.

Снимки документов специально ограничены: без контактов, адресов, медицинских
оценок, квалификационных причин и свободных комментариев результатов.
В списке есть ФИО представителей; в персональном дипломе только ФИО получателя
и профессиональное имя эксперта. Предельный объём общей формы — 1000 регистраций:
сервер возвращает 422 с указанием предела, вместо молчаливой обрезки списка.

## Доступ, версии и файлы

- staff оформляет, исправляет, загружает копии, выпускает и отменяет документы.
- leader читает всё.
- expert читает документы мероприятий, на которые сейчас назначен именно его
  активный профиль. Снятие назначения закрывает чтение, историю и скачивание;
  список также фильтруется. Племенной доступ сохраняется по прежним правилам.
- owner при активном членстве читает персональный диплом, пока остаётся его
  получателем и текущим владельцем собаки. Общие списки/протоколы недоступны.
- admin и veterinarian новых профессиональных прав не получают.

Для другого получателя создают отдельную запись диплома. Передача собаки закрывает
доступ прежнего владельца, не открывая его диплом новому. В owner-истории
before/after=null. За содержание вручную загруженной копии отвечает сотрудник;
она не заменяет автоматические проверки выпуска встроенного шаблона.

Новый файл расходует общую version, требует reason и сохраняется неизменяемо.
После первого файла нельзя менять тип, предмет, получателя, мероприятие или
результат. Исправление или отмена результата отмечает прежний source_changed,
но не переписывает и не удаляет старые байты. При отменённом результате повторный
выпуск диплома запрещён, исторический файл остаётся доступным по обычным правам.

PDF/файловый I/O выполняется вне транзакции доступа; перед фиксацией повторяются
права, версии и снимок источника. Изменение источника во время подготовки даёт
409; незафиксированный файл удаляется. Проверки отзыва доступа повторяются после
чтения с диска. Неизвестный результат commit сохраняет потенциально учтённый файл.

## API и миграция

Используются прежние маршруты `/api/v1/documents`, `.../{id}/generate`,
`.../{id}/files`, `.../{id}/history`. Схемы запросов и ответов — в [OpenAPI](../api/openapi.yaml).
Новые необязательные поля DTO: event_id, event_result_id (положительные int32).
При отсутствии они опускаются; прежние снимки сами по себе не устаревают.
Добавлен фильтр списка `event_id`; повторяющийся или неположительный ID отклоняется.
Категория новых документов general. Типы следует получать из GET /document-types,
а не закреплять числовые ID в клиенте. Эксперту доступны пять типов: два племенных,
список, протокол и диплом; это не раскрывает ему старые дипломы без мероприятия.

Пример общей формы (type_id здесь условный, фактический берётся из API):

```json
{"type_id":12,"event_id":1,"number":"СП-001","issuer":"Клуб","issue_date":"2026-10-17"}
```

Пример диплома:

```json
{"type_id":6,"event_id":1,"event_result_id":1,"dog_id":1,"recipient_member_id":1,"number":"Д-001","issuer":"Клуб"}
```

Генерация:

```json
{"version":1,"reason":"Выдача по итогам мероприятия","template":"event_diploma"}
```

00011 добавляет event_id, event_result_id, два FK, индексы и ограничения сочетаний.
Общие формы имеют предмет-мероприятие без искусственной связи с человеком/собакой;
диплом имеет собаку и соответствующий результат в том же мероприятии. Составной
FK защищает эту тройку дополнительно к сервису. Племенные/медицинские основания
несовместимы с event_id. Новых таблиц нет: 58 прикладных плюс Goose, 110 FK.
Добавлены два типа; прежний «Диплом» используется повторно. Итого 13 типов,
74 значения в 17 справочниках; исходный seed не изменён.

Старые дипломы и документы не перепривязываются и не переклассифицируются.
Down отказывается удалять новые связи или файлы форм; проверять его следует
только на одноразовых БД. Резервирование включает БД и закрытый DOCUMENTS_DIR.

## Проверка

После экспорта окружения:

```bash
export DOGCLUB_TEST_DATABASE_URL="$DATABASE_URL"
go test -race -count=1 -tags=integration ./...
go vet -tags=integration ./...
go build ./...
go mod verify
```

Тесты создают и удаляют собственные БД/файлы. Проверены статусы, отсутствие
результата, отмена и исправление, несколько классов, люди без собак, предел 1000,
неизменность файлов, повторная проверка источника и очистка файла при конфликте,
назначение эксперта, владение/членство, реальные HTTP-ответы OpenAPI и 11 Up/Down.
Для визуальной проверки можно задать DOGCLUB_PDF_TEST_DIR вне Git и выполнить
тесты документов: появятся синтетические формы, включая длинные многостраничные.

Ручной сценарий: опубликуйте мероприятие, назначьте эксперта и запишите человека
и собаку. Напечатайте список; протокол до completed должен дать 422. Зафиксируйте
явку и оценку, завершите мероприятие; выпустите протокол и диплом получателю.
Владелец скачивает диплом и получает 404 для общей формы. Исправьте оценку:
source_changed=true, старый файл тот же. Отмените результат: новый диплом 422.
Снимите назначение эксперта: документы исчезают из его списка, чтение 404.
