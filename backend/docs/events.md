# Мероприятия

Основание: ТЗ, PDF 01, §4.6 (с. 15–16), модуль M6 (с. 27);
актуальное описание, PDF 03, с. 3–4; физическая схема PDF 02, с. 3.
Названия шести типов, классов и оценок берутся из существующих справочников.
Возрастные нормативы, автоматическое присвоение титулов и судейские аккаунты
из старого текстового ФИО не выдумываются.

## Полномочия

| Профиль | Доступ |
| --- | --- |
| staff | Все мероприятия, площадки, классы, расписание, назначение экспертов, запись участников и явка |
| expert | Только назначенные мероприятия: чтение, проверка квалификации, оценки и исправления результатов |
| leader | Чтение всех мероприятий, участников, результатов и истории |
| owner | При активном членстве: календарь без черновиков, собственные записи людей и текущих своих собак, их результаты и ограниченная история |
| admin / veterinarian | Профессионального доступа к модулю нет |

У эксперта проверяется именно назначенный профиль; полномочия профилей не
объединяются. Администратор назначает профиль эксперт-кинолог, сотрудник затем
назначает этот профиль на мероприятие. Блокировка аккаунта/сессии/профиля действует
при следующем запросе. У владельца каждый запрос проверяет членство и текущую
связь с собакой. Прежнее представительство не сохраняет доступ после передачи
собаки. Неактивное членство закрывает весь раздел владельца.

Список участников и чужие результаты владельцу недоступны. ФИО другого
совладельца не выдаётся; история владельца содержит before/after=null,
снимок всей записи внутри результата скрыт. Медицинская проверка возвращает
только состояние допуска и коды оснований, без клинического текста осмотра.

## Модель и процесс

Площадка содержит собственные название и адрес, не привязанные к человеку.
Мероприятие содержит тип, площадку, начало/окончание с явным смещением RFC3339,
часовой пояс IANA (или UTC), аудиторию dogs/people/mixed, признак классов.
Поддерживаются выставки, соревнования, занятия, форумы, конференции и семинары.
Проведённые занятия и индивидуальные результаты учитываются в [журнале дрессировки](training.md).

Переходы: draft → open → closed → in_progress → completed. Из closed можно
вернуться в open; из любого незавершённого состояния можно перейти в cancelled.
Начать мероприятие до starts_at нельзя. Публикация требует заполненной
конфигурации; при использовании классов нужен хотя бы один включённый класс.
Смена состояния не сбрасывает подтверждения квалификации.

Классов может быть несколько или ни одного; названия произвольные. Для класса
задаются необязательные минимальный/максимальный возраст в календарных месяцах,
текст требований и необходимость решения эксперта. Обе возрастные границы
включительны; день в коротком месяце ограничивается последним днём месяца.
Технический диапазон 0–1200 месяцев не является нормативом клуба.
Организатор обязан внести правила конкретного мероприятия.

Слот расписания содержит период внутри мероприятия и необязательный класс.
Без слота используется весь период мероприятия. Возраст определяется на дату
начала выступления в часовом поясе мероприятия. При переносе выступления
проверка пересчитывается. Медицинские записи имеют точность календарного дня
UTC, как в ветеринарном модуле: начало и конец участия переводятся в UTC-даты.
Это отличается от локальной даты для возраста; точное время осмотра не
выдумывается. Дата окончания медицинского действия включительна.

Сотрудник записывает человека либо собаку с представителем из её текущих
владельцев. Собака должна иметь идентификатор; один dog/class не дублируется
даже для разных совладельцев. Человек записывается один раз на мероприятие,
без обязательной собаки, класса и медицинских проверок.
Отменённую запись можно восстановить изменением той же записи в допустимом
состоянии мероприятия. Участие в нескольких классах — отдельные записи собаки.

Создать запись можно только при open. Запись допускается с непрошедшими
проверками: eligibility показывает причины, а регистрация не означает допуск.
Для собаки проверяются представитель, класс, возраст, включённость слота и
медицинский допуск events на весь период участия. Берётся последнее заключение
с датой осмотра не позже начала; отмена/истечение не возвращают старое разрешение.
Новая прививка автоматически не заменяет основания заключения.

По лаб. 3 (fn_get_event_admission) собака с неактивным статусом получает
dog_inactive для мероприятия любого типа. Для «Выставки» и «Соревнования»
родословная должна быть известна на три поколения, иначе pedigree_incomplete.
Достаточно номера и организации документа родословной в карточке собаки; без
документа нужны родители и деды карточками клуба и известные прадеды.
Признак виден в eligibility.dog.pedigree_known_3_generations. Причины проверяются
при каждом пересчёте, поэтому уже созданная запись тоже блокирует явку и результат.

Если класс требует эксперта, назначенный эксперт подтверждает документы и
квалификацию. Для одобрения автоматические проверки должны пройти. Изменение
карточки собаки, правил мероприятия, класса, слота или регистрации делает прежнее
подтверждение неактуальным; возврат прежних значений не восстанавливает его.
Проверяются также текущее назначение и активность подтвердившего эксперта.

Сотрудник фиксирует явку только в in_progress, после начала соответствующего
участия, с повторной проверкой всех оснований. Сохраняется снимок проверки.
После явки использованные класс/слот, правила времени мероприятия и площадка
защищены от переписывания фактов. Неиспользованные классы/слоты можно настраивать,
пока мероприятие не завершено/отменено. Дата рождения собаки не может стать
позже сохранённой даты её участия или неотменённого исторического результата.

Назначенный эксперт вводит для участвовавшей собаки оценку, место и/или комментарий.
Нужно хотя бы одно значение; место положительное. Система не вычисляет победителей
по неизвестным правилам и не присваивает официальный титул из оценки автоматически.
Результат сохраняет снимок явки. Последующая правка медицины не переписывает этот
снимок. Исправление результата возможно в in_progress/completed с причиной и версией.
Отмена сохраняет строку; после неё можно внести новый результат с новым ID.
Одновременно у регистрации может быть только один действующий результат.
Ошибочную явку можно отменить после отмены действующего результата.

## HTTP и версии

Полные DTO, ограничения и ответы — [OpenAPI](../api/openapi.yaml).

| Маршруты под /api/v1 | Назначение |
| --- | --- |
| GET /event-dictionaries, /event-experts, /events/dogs | Справочники, доступные профили экспертов, выбор собак |
| GET/POST /event-venues; GET/PUT /event-venues/{id}; GET .../history | Площадки и история |
| GET/POST /events; GET/PUT /events/{id} | Календарь и карточка |
| POST .../state; PUT .../experts | Состояние и назначения |
| POST .../classes; GET/PUT .../classes/{id} | Классы |
| POST .../schedule; GET/PUT .../schedule/{id} | Время выступлений |
| GET/POST .../registrations; GET/PUT .../registrations/{id} | Участники |
| GET .../registrations/{id}/eligibility | Текущая проверка |
| POST .../registrations/{id}/qualify, /attend, /cancel | Решение, явка, отмена |
| POST .../registrations/{id}/result | Ввод результата |
| GET .../results; GET/PUT .../results/{id}; POST .../results/{id}/void | Результаты |
| GET .../history, .../registrations/{id}/history, .../results/{id}/history | История |

У списков курсор after/limit (по умолчанию 20, максимум 100). Календарь принимает
q/status/type_id/from/to; from/to — RFC3339, фильтр пересечения периодов.
Все маршруты требуют входа. JSON строгий, неизвестные поля отклоняются, тело
не более 16 КиБ. Ошибки RFC9457: 422 validation_failed, 409 event_conflict,
503 events_unavailable, 403 для неподходящего профиля, 404 для скрытых ресурсов.

Изменения требуют version и непустую reason. Создание класса/слота использует
версию мероприятия, исправление — версию класса/слота; версия мероприятия тоже
увеличивается. Ввод результата использует версию регистрации, исправление/отмена —
версию результата. После изменения следует читать актуальный DTO, не угадывать
следующее значение. Отдельная rules_version позволяет отличить изменение правил
от смены состояния. Все изменения и event_changes атомарны в общей
проверяемой auth-транзакции; сбой истории откатывает предметные данные.
Зависимости Handler → Service → Repository, обращения в auth/members/dogs/veterinary
через публичные сервисы в той же транзакции.

## Миграция и проверка

00008_events.sql добавляет шесть таблиц и 19 FK. Существующие адреса копируются
в площадки без создания фиктивных людей. Старый класс сохраняется в отдельной
строке без выдуманных возрастов. Старые даты/время и текст судьи остаются;
часовой пояс и новые точные даты неизвестны и остаются null. Такие события
сначала остаются черновиками и требуют явной настройки сотрудником.
Составной PK achievement сохранён. Дополнительный UNIQUE(achievement_id)
откажет атомарно при неоднозначных старых ID, не удаляя и не выбирая строки.
Down не разрешает потерять новые сведения. Его проверять только на одноразовой БД.

Локальные команды из backend (после экспорта .env, без вывода секретов):

```bash
go test -race -count=1 ./...
export DOGCLUB_TEST_DATABASE_URL="$DATABASE_URL"
go test -race -count=1 -tags=integration ./...
go vet -tags=integration ./...
go build ./...
go mod verify
```

Для ручной проверки запустите API и Mailpit по README. Администратор приглашает
владельца и назначает профили сотрудника, эксперта и ветеринара; каждый входит
с нужным активным профилем. Сотрудник создаёт площадку, событие, класс и слот,
назначает эксперта, открывает запись. Ветеринар оформляет допуск events с
основаниями. Сотрудник записывает собаку, эксперт подтверждает квалификацию.
После closed/in_progress сотрудник фиксирует явку, эксперт — результат.
Проверьте 409 при повторной версии/дубликате, невозможность явки при истёкшем
допуске, устаревание подтверждения после переноса слота, скрытие чужих записей
владельцу и 403 после неактивного членства. Отдельно запишите человека на семинар
без собаки: медицинский допуск не требуется. Исправьте и отмените результат,
проверьте сохранённую историю и отсутствие нового официального титула.

Интеграционные тесты создают и удаляют собственные случайные базы. Покрыты
возраст/конец месяца/часовые пояса, UTC-граница осмотра, медицинские основания,
перенос и возврат расписания, назначения, текущие владельцы/членство, конкурентные
версии, откат при сбое истории, наследуемая схема и реальные HTTP-ответы OpenAPI.
Многотуровые соревнования не реализованы. Связанные процессы описаны в разделах
[уведомлений](notifications.md) и [дрессировки](training.md); React-клиент в репозиторий не входит.

Список участников, итоговый протокол и диплом описаны в разделе
[документов мероприятий](documents-events.md). Титулы из оценки
не присваиваются; source_changed не переписывает прежние PDF.
