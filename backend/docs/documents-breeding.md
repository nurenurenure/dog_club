# Регистрационные и племенные документы

Реализованы свидетельство о регистрации собаки, заключение о вязке и акт о
регистрации помёта. Общий реестр, закрытые файлы, история и резервирование —
[documents.md](documents.md). Формы мероприятий описаны в [documents-events.md](documents-events.md),
сводная отчётность — в [reports.md](reports.md).

## Подтверждённая дата регистрации

В карточке собаки есть необязательная registration_date. Это подтверждённая
дата постановки на учёт клуба, отдельная от даты рождения, идентификации,
выдачи свидетельства и технического создания записи в системе. Миграция не
подставляет даты старым собакам из журналов или текущего времени.

Сотрудник подтверждает/исправляет дату отдельным запросом:

```http
PUT /api/v1/dogs/{dogID}/registration
Content-Type: application/json
```

```json
{"version":1,"reason":"Проверено по первичному документу","registration_date":"2023-03-02"}
```

Нужны версия карточки и непустая причина до 500 символов. Дата должна быть не
раньше рождения и не позже текущей даты UTC. Явный null снимает подтверждение;
отсутствующее поле не принимается. Изменение атомарно увеличивает общую версию
собаки и пишет dog_changes. Правка рождения, противоречащая подтверждённой дате,
также отклоняется. История прежних дат не удаляется.

В ответе Dog поле registration_date присутствует, когда дата известна; иначе
оно опущено. Новое пустое поле не меняет старые снимки PDF само по себе. Поле не
добавляется в краткий список собак: дату читают в полной карточке.

## Шесть форм в общем реестре

| template | Тип документа | Основание |
| --- | --- | --- |
| member_card | Карточка члена клуба | Человек |
| dog_card | Карточка собаки | Собака |
| veterinary_conclusion | Ветеринарная справка | Конкретный осмотр, необязательное заключение о допуске |
| registration_certificate | Регистрационное свидетельство | Собака с подтверждённой датой и получателем-владельцем |
| breeding_conclusion | Заключение о вязке | breeding_decision_id — конкретное решение эксперта |
| litter_act | Акт о регистрации помёта | litter_id — зарегистрированный помёт |

Для новых племенных документов category=breeding. К одиннадцати типам относятся
девять прежних и два новых: «Заключение о вязке», «Акт о регистрации помёта».
Регистрационное свидетельство использует прежний тип, новый дубликат не создаётся.

Запись документа сохраняет dog_id и необязательного recipient_member_id по
прежней модели. Для племенного документа дополнительно нужно ровно одно
соответствующее основание. Собака должна относиться к решению (самка/самец)
или помёту (родитель либо связанный зарегистрированный щенок). Свидетельство
о регистрации не использует племенных оснований.

Пример реквизитов персонального заключения; реальные ID выбирают из API:

```json
{
  "type_id":10,
  "number":"КЛ-001",
  "issuer":"Клуб собаководства",
  "dog_id":1,
  "recipient_member_id":1,
  "breeding_decision_id":1
}
```

Генерация использует прежний маршрут POST /documents/{documentID}/generate:

```json
{"version":1,"reason":"Выдача заключения","template":"breeding_conclusion"}
```

Номер/дата выдачи документа вводятся явно, не выводятся из ID решения или даты
регистрации собаки. Неизвестные реквизиты печатаются как неизвестные.

## Решение эксперта и факты помёта

Решение принимает expert в breeding; сотрудник оформляет PDF без изменения
результата. Отказ печатается как отказ. Перед новым выпуском проверяются выбранное
решение, его связь с заявкой, последнее решение и текущее состояние/пара/плановая
дата заявки. Изменённая или отменённая заявка блокирует выпуск по старому решению.
Факт проведённой вязки сам по себе не отменяет решение: дополнительная техническая
версия заявки после проведения не делает его неактуальным.

Пара в заключении показана по сохранённой оценке эксперта на момент решения.
Форма содержит дату решения и плановую дату вязки раздельно. Она не заменяет
повторную проверку медицинского допуска перед фактической вязкой.
ФИО эксперта берётся по его профилю и связанной карточке человека; если связи нет,
ФИО отмечено как неизвестное, логин вместо ФИО не подставляется. Отключённый
профиль остаётся опознаваемым в истории, но не получает доступа к API.

Акт помёта показывает родителей, дату рождения, общее число щенков и отдельно
число зарегистрированных с идентификаторами. Зарегистрированные щенки перечислены
без данных их владельцев. Неизвестные идентификаторы незарегистрированным щенкам
не придумываются. При фактическом интервале менее 365 дней нарушение явно
попадает в акт; сам факт рождения остаётся доступным для документирования.
Предельный объём одной формы — 1000 зарегистрированных щенков, без обрезки списка.

## Клубный экземпляр и персональная копия

- staff создаёт, исправляет, загружает копии, формирует и отменяет обычные и
  племенные документы. Медицинские документы оформляет veterinarian.
- leader читает все документы.
- expert читает только племенные документы, их файлы и историю; его список типов
  также ограничен племенными. Эксперт не выпускает PDF и не меняет реестр.
- owner читает разрешённую персональную копию при активном членстве и сохранении
  текущего владения собакой, указанной в документе. Администратор не получает
  профессионального доступа автоматически; veterinarian не читает племенные документы.

У племенного документа без recipient_member_id клубный экземпляр, недоступный
владельцам. С получателем — персональная копия: снимок не включает комментарий
заявки, причину решения и клинические оценки пары. В ней остаются результат,
основание, сведения о собаках и профессиональное имя эксперта. Контактов и адресов
других владельцев нет. Полный и персональный экземпляры — отдельные записи
реестра; нельзя добавить полный PDF в ту же запись и случайно открыть его владельцу.
За содержание вручную загруженной копии отвечает оформляющий сотрудник.

После первого файла нельзя менять предмет, получателя, тип, решение или помёт.
Для другого получателя/основания создают отдельный документ. При передаче собаки
старый получатель теряет доступ; новый владелец автоматически его не получает.
Блокировки и членство повторно проверяются при скачивании. В owner-истории
before/after=null, внутренние снимки источников и файловые пути не выдаются.

Прежние PDF не переписываются при правке заявки, помёта или даты регистрации.
GET документа рассчитывает source_changed; снятие подтверждения даты блокирует
новое свидетельство, но не уничтожает прежний PDF. Генерация и диск работают вне
транзакции, перед фиксацией снова проверяются доступ, версия и источники.

## Миграция и проверки

00010_registration_breeding_documents.sql добавляет поле даты, две ссылки на
основания и расширяет допустимые категории/шаблоны. Новых таблиц нет: остаются
59 с Goose; FK стало 108. Существующие записи и их неизвестные даты сохраняются.
Down отказывается терять подтверждённые даты, историю этих дат, новые основания
или новые формы. После снятия подтверждения журнал всё равно защищает сведения
от отката. Проверять Down нужно только на одноразовой БД.

На PostgreSQL проверяются десять Up/Down, сохранение прежних документов,
неизвестные даты, отказ при попытке потери подтверждения, шесть форм, решения
approved/rejected/устаревшее, печать после проведения вязки, нарушение интервала,
полномочия, персональный снимок без клиники, передача собаки и членство.
Дополнительные поля и значения enum описаны в [OpenAPI](../api/openapi.yaml);
необязательные поля сохраняют совместимость прежних DTO. Визуальная проверка включает кириллицу
и акт из 80 тестовых щенков на пяти страницах.

После экспорта окружения:

```bash
export DOGCLUB_TEST_DATABASE_URL="$DATABASE_URL"
go test -race -count=1 -tags=integration ./...
go vet -tags=integration ./...
go build ./...
go mod verify
```

Для ручной проверки подтвердите дату собаки и сформируйте свидетельство; снимите
подтверждение и убедитесь в 422 при новой генерации и неизменности старого файла.
По решению эксперта создайте клубный экземпляр и отдельную персональную копию.
Владелец должен получить 404 для клубного; expert — прочитать племенной документ
и получить 404 для чуждого его полномочиям регистрационного свидетельства.
Измените заявку: выпуск по прежнему решению должен отклоняться, старый PDF
сохраниться. По помёту сформируйте акт и проверьте количество, даты и историю.
