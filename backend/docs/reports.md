# Сводный отчёт о деятельности клуба

Отчёт о деятельности клуба доступен staff и leader. Admin, veterinarian, expert
и owner не получают этот доступ автоматически; активен один профиль сессии.
Основание: ТЗ, PDF 01, с. 12 и M8 на с. 27. Графики, медицинская аналитика,
архив выпусков и восстановление состояния клуба на прошлую дату отложены.

## Период и показатели

Обязательны from/to в формате YYYY-MM-DD, обе границы включительны, from <= to.
Поддерживаются годы 0001–9999. Параметры не подставляются автоматически; допустим
период любой длины в этом диапазоне. Будущий период не означает прогноз: считают
только уже записанные факты с подходящими предметными датами и статусами.

| activity | Смысл |
| --- | --- |
| members_joined | Члены с известной датой вступления внутри периода, независимо от текущего статуса |
| dogs_registered | Собаки с подтверждённой registration_date внутри периода, независимо от текущего статуса |
| events_completed | Мероприятия с текущим статусом completed и местной датой окончания в периоде |
| events_by_type | Те же мероприятия по типам; все типы, включая нулевые, в порядке ID |
| matings_performed | Только «Проведена», с известной фактической датой в периоде |
| litters_born | Помёты с датой рождения в периоде |
| puppies_born | Сумма total_puppies этих помётов, включая ещё не зарегистрированных щенков |

Вступление и дата вязки из старых timestamp берутся как сохранённый календарный
день, без придумывания часового пояса. Дата окончания мероприятия рассчитывается
в его timezone, а не в UTC или часовом поясе PostgreSQL-сессии. Неполные даты или
неизвестный PostgreSQL часовой пояс исключают мероприятие из периодного счётчика
и попадают в показатель полноты. Черновики, отменённые и незавершённые мероприятия
не считаются проведёнными. Вязки «Запланирована»/«Отменена» исключены.

Совладельцы, несколько классов/регистраций и результаты не умножают количество
собак или мероприятий. Данные об общем числе щенков не заменяются количеством
карточек собак или связей litter_dog. Старые даты не восстанавливаются по аудиту,
созданию записи, идентификации собаки или выдаче документа.

## Текущие итоги и полнота дат

current отражает состояние **на момент формирования**:

- member_cards — все карточки членов клуба;
- active_members — карточки со статусом «Активный»;
- dog_cards — все карточки собак;
- dogs_on_register — карточки со статусом «На учёте».

Это не состояние на конец выбранного периода. Показатели data_quality также
относятся ко всей текущей базе, а не к неизвестному прошлому периоду:

- members_without_membership_date — карточки с неизвестной датой вступления;
- dogs_without_registration_date — собаки без подтверждённой даты регистрации;
- performed_matings_without_date — проведённые вязки без фактической даты;
- events_without_period — мероприятия любого статуса без полных начала/окончания
  или известного часового пояса.

Нулевые значения не скрываются. Ответ не содержит ФИО, контактов, идентификаторов
животных, индивидуальных результатов или клинических сведений.

## API и экспорт

```http
GET /api/v1/reports/club-activity?from=2024-02-01&to=2024-02-29
GET /api/v1/reports/club-activity/export?from=2024-02-01&to=2024-02-29&format=pdf
GET /api/v1/reports/club-activity/export?from=2024-02-01&to=2024-02-29&format=csv
```

Нужен Bearer access JWT активного профиля staff/leader. Параметры обязательны,
неизвестные, повторяющиеся, повреждённые и некорректные значения дают 422
в общем формате RFC 9457. На JSON-маршруте format не разрешён; экспорт принимает
только pdf/csv. Без входа 401, без профессионального права 403, недоступная БД 503.
Актуальные маршруты и схемы описаны в [OpenAPI](../api/openapi.yaml).

JSON включает period, generated_at (UTC), methodology, activity, current,
data_quality. Каждый запрос вычисляет новый результат по актуальным исправленным
данным. PDF и CSV используют те же показатели, период и пояснение методики.
Раздельные запросы могут отличаться при изменении исходных данных; generated_at
указывает момент конкретного расчёта. CSV включает эту метаинформацию в каждой
строке, PDF — в заголовке и пояснении.

Экспорт отдаётся attachment с no-store, nosniff и CSP sandbox. CSV — UTF-8 с BOM
для табличных программ, запятая как разделитель и CRLF, кавычки/запятые/переносы
экранируются encoding/csv. Колонки:

```text
scope,metric,event_type_id,label,value,from,to,generated_at,methodology
```

Одна строка на показатель; event_type_id заполнен только для разреза мероприятий.
Числа остаются числовыми; потенциальные формулы в текстовых ячейках получают
защитный апостроф. PDF создаётся существующими fpdf/DejaVu, поддерживает кириллицу
и перенос страниц; лицензионные уведомления — в THIRD_PARTY_NOTICES.md.

## Архитектура и хранение

reports.Handler проверяет HTTP-параметры, reports.Service собирает показатели
через публичные members/dogs/breeding/events.Service в одной WithAccess-транзакции.
Агрегирующий SQL находится в репозиториях соответствующих модулей; персональные
карточки и приватные репозитории не передаются в reports. Общий reporting.Period
содержит только календарные границы и их проверку.

Действующий транзакционный механизм сериализует чтение с изменениями через API;
отчёт не объединяет промежуточные состояния такой транзакции. На запросы действует
существующий таймаут auth I/O. PDF/CSV формируются в памяти вне транзакции; перед
выдачей экспорта повторно проверяются блокировка, сессия и активный профиль.

Нет записи в document/document_file, файлов в DOCUMENTS_DIR, фоновых задач,
новых таблиц, миграций или зависимостей. Серверного архива и истории выпусков нет;
сохранённые пользователем файлы не изменяются при следующем расчёте. Бэкап проекта
по-прежнему включает БД и закрытый каталог документов; новых путей не появляется.

## Проверка

После экспорта окружения:

```bash
export DOGCLUB_TEST_DATABASE_URL="$DATABASE_URL"
go test -race -count=1 -tags=integration ./...
go vet -tags=integration ./...
go build ./...
go mod verify
```

Интеграционные тесты создают и удаляют только свои БД. Проверяются нули, границы
периода, високосный день, местные даты/неизвестные зоны, текущие статусы,
неполные даты, совладельцы/классы, число щенков, согласованность чтения,
исправления дат, все профили и отзыв доступа, реальные HTTP-ответы OpenAPI,
совпадение чисел JSON/CSV, заголовки и безопасные логи. PDF проверяется визуально.
DOGCLUB_REPORT_REVIEW_DIR вне Git позволяет сохранить синтетические PDF из тестов.

Ручной сценарий: создайте карточку с датой вступления и собаку с подтверждённой
датой регистрации. Получите JSON за соответствующий период, затем PDF и CSV.
Числа должны совпасть при неизменных данных. Исправьте дату за пределы периода:
периодный счётчик уменьшится, текущие итоги сохранятся. Снимите подтверждение
даты собаки: она перейдёт в показатель полноты дат. Проверьте 403 для остальных
профилей и отсутствие новых документов/файлов после экспорта.
