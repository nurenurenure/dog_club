# Результаты проверки backend

Дата: 17 октября 2026. Объём: локальная эксплуатация backend, без React,
изменений предметной схемы и новых миграций. Сценарии и команды воспроизведения
приведены в [operations.md](operations.md) и `scripts/verify.py`.

## Среда и автоматические проверки

Go 1.26.0; SDK `golang:1.26.0-bookworm`; runtime `debian:bookworm-slim`,
UID/GID 65532; PostgreSQL 18.6; Mailpit v1.31.6; Docker Compose 5.3.1 на macOS.
Docker выделено 10 CPU и 8 321 515 520 байт памяти. Измерения относятся к этому
локальному окружению, его ресурсам и указанному набору данных.

Успешно выполнены на хосте и в SDK-контейнере:

```sh
go mod verify
go vet ./...
go build ./...
# С DOGCLUB_TEST_DATABASE_URL, тесты сами создают отдельные случайные базы.
go test -race -tags=integration ./...
```

Контейнерная команда: `docker compose run --build --rm -T checks` выполнялась
с отдельным проектом `dogclub_stage12_checks`. Предметные тесты проверяют права,
версии/конкурентные исправления, атомарность истории, медицинские основания,
племенные ограничения, мероприятия, документы, отчёты, уведомления и Training.
Добавлены проверки многопоточных метрик без сырых параметров, учёта восстановленного
panic-ответа, успешного/прерванного цикла worker и явных ограничений Compose SMTP.

OpenAPI полностью проходит валидацию и сверку с маршрутизатором. Отдельное
семантическое сравнение с состоянием `ccb5e22` до добавления метрик подтвердило: все прежние
149 операций и схемы сохранены; добавлена одна операция метрик и её схема,
всего 150 операций. Проверены синтаксис shell/Python и `git diff --check`.

## Сквозной Docker-сценарий

`scripts/verify.py` использует собственные проекты `dogclub_verify_*`, случайные
секреты и loopback-порты. Рабочая `.env` не читается. Синтетический набор:
100 собак, 3 карточки людей, 2 аккаунта (несколько профилей администратора),
осмотр, проведённая дрессировка, завершённый семинар, реестр и два настоящих PDF.
Подготовка 50 отдельных staff-сессий соблюдает штатное ограничение входа 10/мин.

Проверки охватывают чистый запуск всех 13 миграций, приватные права каталога,
bootstrap и приглашение через Mailpit, активацию/вход, разграничение профилей,
журнал Training и отзыв допуска, медицинское заключение, документы и скачивание,
событие и отчёт, неактивное членство, смену владельца, блокировку аккаунта,
автоматическую отправку и сохранение попытки при сбое SMTP, повторную доставку,
идемпотентный запуск/сохранение данных, liveness/readiness при остановленной БД
и восстановление readiness после её запуска. Ускорение времени повторной попытки
выполняется только SQL-изменением срока в одноразовой тестовой БД.

Полный сценарий завершился успешно с exit 0. Непустая БД и оба PDF сохранены
скриптом backup, API возобновлён. В отдельном новом проекте выполнен pg_restore,
сверен `storage.json`, проверены размеры/SHA-256 обоих файлов (76 298 байт),
66 таблиц и версия миграций 13. Скачанный PDF байт-в-байт совпал с исходным. Очередь сохранена, worker выключен,
last_successful_cycle_unix=0. Повторное восстановление поверх того же проекта
и копия с изменённым documents.tar отклонены; повреждённая копия не создала проект.
API-логи проверены на отсутствие тестовых паролей, JWT, ключа и клинического текста.
Тестовые проекты и их тома удалены; рабочие тома сохранены.

Нагрузка: 50 отдельных предварительно открытых staff-сессий; синхронный старт
клиентов, без пауз между запросами в серии. Сценарии запускались последовательно:
200 поисковых запросов (по 4 на клиента) и 100 PDF-экспортов (по 2 на клиента).
Показатели — время полного HTTP-запроса на компьютере, включая чтение ответа.

| Сценарий | Запросы | Ошибки | p50, мс | p95, мс | max, мс | Предел |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| `/dogs?q=Synthetic&limit=50` | 200 | 0 | 51,06 | 103,61 | 114,09 | ≤2000 мс |
| PDF `/reports/club-activity/export` | 100 | 0 | 389,88 | 418,01 | 422,78 | ≤3000 мс |

Все измеренные запросы уложились в заданные пределы. Оптимизаций, ослабляющих
проверки доступа или общий транзакционный guard, не потребовалось.
JSON последнего полного прогона — `var/stage12-verification.json` (вне Git).

## Рабочий запуск

`docker compose up -d --wait api` завершился успешно. PostgreSQL осталась в
прежнем контейнере/томе, мигратор применил 0 новых версий, API работает как
non-root и публикуется на 127.0.0.1:8080. Liveness/readiness — 200;
`operations/metrics` и Training без входа — 401. `/maintenance` подтвердил
66 таблиц, версию 13, 0 зарегистрированных файлов. До запуска проверены
нулевые количества аккаунтов, членов, собак и файлов; синтетические данные
остались только в удалённых тестовых проектах. Исходный пустой `var/documents`
сохранён. Для рабочего хранилища создан новый постоянный `documents_data`.

## Практические границы

Нагрузка — локальный поиск среди 100 собак и PDF сводного отчёта с 50 одновременно
работающими клиентами. Это проверка требований ТЗ (PDF 01, стр. 20: поиск ≤2 с,
документ ≤3 с, до 50 пользователей) на описанном наборе, а не доказательство
таких же значений на произвольной будущей базе. Долговременный SLA 99% этим
испытанием не измеряется. Выдача отдельных больших документов ограничивается
действующими пределами предметных модулей.

React, публичное размещение/TLS, внешний SMTP, REST-ящик уведомлений/WebSocket,
внешние интеграции, Prometheus/Grafana/ELK/Telegram остаются отдельным объёмом.
Рабочая БД не заполнялась синтетическими пользователями/собаками. Старый каталог
документов на хосте сохраняется.
