# Учёт дрессировки

Основание: актуальное описание предметной области, PDF 03, стр. 3;
физическая схема и SQL PDF 02, стр. 3, 10, 16, 19. Используются прежние
`dog_training_session`, `training_type` и четыре согласованных вида дрессировки.
Модуль — журнал уже проведённых занятий, без новых курсов, групп, расписания,
платежей, сертификатов, писем или показателей отчёта.

## Полномочия

| Профиль | Чтение | Запись |
| --- | --- | --- |
| admin | Виды дрессировки, допуски и история допусков | Назначает, изменяет и отзывает допуски |
| staff | Все занятия; список инструкторов без приватного основания допуска | При явном допуске — свои занятия по разрешённым видам |
| leader | Все занятия; список инструкторов без приватного основания допуска | Нет |
| owner | Виды и занятия текущих своих собак при активном членстве | Нет |
| veterinarian, expert | Нет профессионального доступа к журналу Training | Нет |

Инструктор — сотрудник с отдельным допуском администратора, а не новая роль.
Нужны активный подтверждённый аккаунт, включённый профиль staff, привязанная
карточка человека, включённый допуск и разрешённый вид дрессировки. Активное
личное членство для профессиональной работы не требуется. При неактивном
членстве закрывается owner, но сохраняется профессиональный профиль.

Права не объединяются: admin или veterinarian с дополнительным профилем staff
должен выбрать staff, чтобы работать инструктором. Проверки аккаунта, профиля,
членства владельца и текущего допуска выполняются в БД при каждой операции.
Отзыв допуска или удаление вида из разрешённых закрывает запись/исправление/
отмену по соответствующему виду; чтение staff и история сохраняются. Статус
`available` в списке учитывает текущую доступность аккаунта и профиля.

## Допуски

Все пути ниже имеют префикс `/api/v1`.

- `GET /training-types` — четыре существующих вида; новые справочные значения
  через API не добавляются.
- `GET /training-instructors?after=PROFILE_ID&limit=50` — список допусков;
  `next_after` — строка профиля. Администратор видит `qualification`, staff/leader — нет.
- `PUT /training-instructors/{profileID}` — полный набор разрешений, только admin.
- `GET /training-instructors/{profileID}/history?after=0&limit=50` — только admin.

Пример первого назначения:

```json
{
  "version": 0,
  "reason": "Назначение инструктора",
  "enabled": true,
  "qualification": "Квалификация проверена ответственным сотрудником клуба",
  "type_ids": [1, 4]
}
```

Все пять полей обязательны; null не допускается. Для первого назначения
`version=0`, затем — текущая версия допуска. Виды должны существовать,
не повторяться, максимум 100. Включённый допуск требует хотя бы один вид;
при отключении допустим пустой массив. Основание — до 1000 символов,
причина — до 500, без управляющих знаков. Создание аккаунта или профиля
само по себе допуск не назначает. Допуск разрешает внесение сведений сейчас;
система не выдумывает подтверждение прошлой квалификации из даты занятия.

## Журнал занятий

- `GET /training-sessions` — список с пагинацией и фильтрами `dog_id`, `type_id`,
  `instructor_profile_id`, `from`, `to`.
- `POST /dogs/{dogID}/training-sessions` — новое проведённое занятие, ответ 201
  и Location карточки записи.
- `GET /dogs/{dogID}/training-sessions/{sessionID}` — запись.
- `PUT /dogs/{dogID}/training-sessions/{sessionID}` — исправление автором.
- `POST /dogs/{dogID}/training-sessions/{sessionID}/void` — отмена ошибочной записи.
- `GET /dogs/{dogID}/training-sessions/{sessionID}/history` — история записи.

Пример факта без связи с мероприятием:

```json
{
  "type_id": 1,
  "starts_at": "2026-10-16T10:00:00+07:00",
  "ends_at": "2026-10-16T11:00:00+07:00",
  "timezone": "Asia/Barnaul",
  "result": "Отработаны команды послушания",
  "event_id": null,
  "registration_id": null
}
```

Инструктор и автор определяются по текущему профилю, в теле запроса их нет.
Результат — до 2000 символов, доступен владельцу; приватные кадровые и клинические
сведения в него не включаются. Даты — RFC3339 с явным смещением; `timezone` —
явный IANA/UTC, без `Local`. Начало не позже окончания, окончание не в будущем,
локальная дата начала не раньше даты рождения. Поле рождения также нельзя
впоследствии перенести позже подтверждённого неотменённого занятия.

PUT содержит те же поля и дополнительные `version`, `reason`. Пропуск связи
или два null очищают связь; для сохранения передайте оба текущих ID. Автор
не меняется. Исправление требует текущего допуска к старому и новому видам.
Для void достаточно `version`, `reason`. Физического удаления и восстановления
void нет; при необходимости создают правильную новую запись. Точный дубль
активного факта (собака, вид, инструктор, начало, окончание) возвращает 409.

`after` списка занятий — непрозрачное целое число из `next_after`: оно учитывает
составной ключ ID занятия + ID собаки. Его не следует конструировать из ID записи.
У истории `after` — ID изменения. `limit` — от 1 до 100, по умолчанию 50.
`from`/`to` — включительные границы времени начала, RFC3339 со смещением.
Записи с неизвестным моментом времени не включаются в фильтр по этому моменту.
Неизвестные, повторные, пустые или некорректные параметры отклоняются.

Владелец после передачи собаки теряет доступ; новый владелец получает журнал
этой собаки. Владелец не видит полные before/after и причины исправлений в
истории. Профили администратора, эксперта и ветеринара не наследуют права staff.

## Мероприятие и медицинский контроль

Связь задаётся парой `event_id` + `registration_id`. Регистрация должна относиться
именно к этой собаке, тип мероприятия — «Занятие». При новой связи мероприятие
не draft/cancelled, регистрация не cancelled; фактический период находится
внутри мероприятия или выбранного включённого слота. Участник-человек не
подменяет регистрацию собаки. Training не назначает эксперта и не подтверждает
явку автоматически. Отсутствие подтверждённой явки даёт `attendance_unconfirmed`.

`event_snapshot` сохраняет только ID, версии, тип, статусы и время основания,
без чужого ФИО, контактов, причин, клиники и комментариев. После изменения
мероприятия/регистрации исходный снимок и факт занятия сохраняются, а
`source_changed` и `event_source_changed` показывают отличие от текущего основания.
Изменение собаки в использованной регистрации ограничено внешним ключом.

Для всех новых фактов, в том числе независимых от мероприятий, используется
существующий ветеринарный допуск назначения `events` на UTC-даты всего периода.
Новых медицинских нормативов или назначения допуска Training не создаёт.
Отсутствующий, истёкший или отозванный допуск даёт `medical_clearance`, но не
препятствует сохранению факта уже состоявшегося занятия.

`medical_snapshot` — результат проверки при внесении/исправлении; он сохраняется
с `checked_at`. `current_medical` — повторная проверка на те же фактические даты
с учётом текущих исправлений медицинских оснований. Изменение медицины не
перезаписывает старый снимок и не увеличивает версию занятия. В этих объектах
только решение и коды причин; свободный текст осмотров/диагнозов не выдаётся.

## Старые данные и миграция

Миграция 00013 сохраняет составной PK и старые timestamp без часового пояса,
добавляет подтверждённые время/автора/результат/снимки и три таблицы:
`training_instructor`, `training_instructor_type`, `training_changes`.
Фиксация допуска, разрешённых видов или занятия и его истории атомарна в общей
WithAccess-транзакции. Межмодульные проверки используют публичные сервисы.

Для старой записи возвращаются `legacy=true`, исходные `legacy_starts_at` и
`legacy_ends_at` без придуманного часового пояса, `legacy_incomplete`. Автор,
результат, квалификация, привязка к аккаунту/мероприятию и медицинская оценка
автоматически не назначаются. Такие записи доступны для чтения; редактирование
при неизвестном авторе не разрешается. Отдельный процесс уточнения старых
сведений не реализован. Down отказывается удалять допуски, новые
подтверждённые занятия или историю; старые строки и даты при пустом откате
сохраняются.

## Проверки и локальный запуск

После загрузки локального окружения:

```sh
go test ./...
DOGCLUB_TEST_DATABASE_URL="$DATABASE_URL" go test -race -tags=integration ./...
go vet ./...
go build ./...
go run ./cmd/migrate up
go run ./cmd/api
```

Интеграционные тесты создают и удаляют только отдельные случайные БД. Проверяются
права профилей, явные допуски, неактивное личное членство инструктора, отзыв допуска,
собственные исправления, конкурентные версии, откат при ошибке истории,
медицинские предупреждения и изменения оснований, связь с мероприятием,
составные ID, передача собаки, legacy-данные, безопасный Down и JSON/OpenAPI.
API никогда не запускает миграции сам. Ручной сценарий: admin выдаёт допуск
существующему staff, тот вносит занятие; активный owner читает его по своей собаке.
